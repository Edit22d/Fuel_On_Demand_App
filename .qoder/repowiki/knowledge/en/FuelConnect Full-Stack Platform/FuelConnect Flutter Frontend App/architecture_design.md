Single-package Flutter app rooted at `lib/main.dart` which bootstraps system UI, initializes `auth`, then runs `FuelOnDemandApp`. The app uses a custom in-memory navigation stack (`AppState` in `core/app_state.dart`) rather than `go_router`; `Shell` is the only Scaffold and dispatches the active `Screen` enum value to concrete widgets via a large switch. Screens are grouped by domain into `screens/{auth,browse,order,rider,account,extra_customer}_screens.dart` plus `missing_screens.dart` (a placeholder registry) and `sheets.dart`. Cross-cutting concerns live under `core/`: `app_state.dart` (navigation + order/wallet/rewards state), `theme.dart` + `icons.dart` + `widgets.dart` (design tokens, reusable components), `data.dart` (domain models like Vehicle/Place/PayMethod), and rider/account extra states. Services layer (`services/auth_service.dart`, `services/api_client.dart`) encapsulates persistence and network; `AuthService` is currently a local mock using `shared_preferences` with salted SHA-256 password hashing, explicitly marked as a stand-in for future API calls. Platform shells (`android/`, `ios/`, `web/`) are standard Flutter-generated projects with no custom platform logic beyond `MainActivity.kt` / `AppDelegate.swift`.
