Monolithic NestJS application organized as a feature-module tree under `src/`, with each domain (`auth`, `orders`, `payments`, `riders`, `customers`, `stations`, `reviews`, `support`, `tracking`, `notifications`, `wallets`, `admin`) owning its controller, service, DTO folder, and module. Cross-cutting concerns live in `src/common/` (guards, decorators, interceptors, filters, validators, geo utilities) and are wired globally from `AppModule` via `APP_GUARD` / `APP_INTERCEPTOR` / `APP_FILTER` providers: `ThrottlerGuard`, `JwtAuthGuard`, `RolesGuard`, `AuditLogInterceptor`, and `AllExceptionsFilter`. Data access goes through a shared `PrismaModule` wrapping `@prisma/client`; Redis is provided by `RedisModule` and used as both a cache store and the Socket.IO adapter for real-time tracking (`tracking/realtime.gateway.ts`). Configuration is centralized in `config/configuration.ts` (typed `AppConfig`) validated at startup by `envValidationSchema` (Joi), loaded via `ConfigModule.forRoot`. The bootstrap in `main.ts` configures Helmet, CORS, global prefix (`api/v1`), Swagger UI (`/docs`), static dashboard assets (`/dashboard`), and a global `ValidationPipe` that whitelists DTOs and transforms payloads. A single-page dashboard lives under `public/dashboard/` and is served without a build step. Docker multi-stage build compiles TypeScript into `dist/` and runs the Node runtime on Alpine.
